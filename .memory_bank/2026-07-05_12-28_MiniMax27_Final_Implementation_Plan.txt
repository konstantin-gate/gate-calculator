### P0-2. Исправить ошибку `char.lowercased() == "pi"` в Tokenizer

**Проблема:** Sonnet #E-01
**Файл:** `Sources/CalculatorEngine/Tokenizer/Tokenizer.swift`, строка 90
**Верификация:** ✅ Подтверждено. `char` — это `Character`. `char.lowercased()` возвращает `String`. Один символ (например "p") никогда не равен строке "pi".

**Действие:**
Заменить строку 90:
```swift
// БЫЛО (неверно):
if char == "\u{03C0}" || char == "π" || char.lowercased() == "pi" {

// СТАЛО (верно):
if char == "\u{03C0}" || char == "π" || (char.lowercased() == "p" && {
    let nextIdx = cleaned.index(after: i)
    return nextIdx < cleaned.endIndex && cleaned[nextIdx] == "i"
}()) {
```

Упрощённый вариант — просто проверить `"pi"` как подстроку начиная с текущей позиции:
```swift
if char == "\u{03C0}" || char == "π" {
    // уже обработано
} else if char == "p" || char == "P" {
    let nextIdx = cleaned.index(after: i)
    if nextIdx < cleaned.endIndex && cleaned[nextIdx] == "i" {
        let afterNext = cleaned.index(after: nextIdx)
        if afterNext >= cleaned.endIndex || !cleaned[afterNext].isLetter {
            tokens.append(.number(Decimal.pi))
            advance(&i, in: cleaned)
            advance(&i, in: cleaned) // пропустить "i"
            continue
        }
    }
    throw CalculatorError.invalidCharacter(String(char))
}
```

**Примечание:** Если символ 'p'/'P' не является частью "pi" (например за ним идёт пробел или оператор), следует выбросить `invalidCharacter`. Однако для упрощения можно просто удалить проверку `"pi"` как ключевого слова, поскольку 'π' и 'e' уже обрабатываются.

### P0-3. Parser: extraClosingParenthesis вместо missingClosingParenthesis

**Проблема:** Sonnet #E-03
**Файл:** `Sources/CalculatorEngine/Parser/Parser.swift`, строки 84-86
**Верификация:** ✅ Подтверждено. Для выражения `(15+16` токенизатор даёт `[leftParen, number(15), binaryOp(+), number(16)]`. При toRPN leftParen кладётся в стек, 15 и 16 уходят в output, + кладётся в стек. После end of tokens: `operatorStack = [leftParen, +]`. popLast() даёт '+', не leftParen, выхода нет. operatorStack.popLast() даёт leftParen. `if top.isLeftParen || top.isRightParen` — isLeftParen=true → throw extraClosingParenthesis. Но это НЕ extra closing, это missing closing.

**Действие:**
Заменить строки 84-89:
```swift
// БЫЛО:
while let top = operatorStack.popLast() {
    if top.isLeftParen || top.isRightParen {
        throw CalculatorError.extraClosingParenthesis
    }
    output.append(top)
}

// СТАЛО:
while let top = operatorStack.popLast() {
    if top.isLeftParen {
        throw CalculatorError.missingClosingParenthesis
    }
    if top.isRightParen {
        throw CalculatorError.extraClosingParenthesis
    }
    output.append(top)
}
```

// appendOperator (строки 44-48):

## ЧАСТЬ 2. СЕРЬЁЗНЫЕ ИСПРАВЛЕНИЯ (P1)

### P1-1. Потенциальные бесконечные циклы в Tokenizer

**Проблема:** UnslothMTP 8.1-8.10
**Файл:** `Sources/CalculatorEngine/Tokenizer/Tokenizer.swift`
**Верификация:** ✅ Подтверждено частично. "1..5" — бесконечный цикл. "." — не бесконечный цикл (readNumber возвращает (0, start) и advance вызывается после return). "0x", "0b", "0o" без цифр — НЕ бесконечный цикл, возвращают 0 корректно.

**Действие:**
Для "1..5": readNumber("1..5", from: 0) читает "1", останавливается на первом ".", возвращает (1, index_of_first_dot). advance переходит на первый ".", readNumber("1..5", from: first_dot) начинает с ".", isNumber=false, цикл не выполняется, numberStr="", return (0, start). i не продвинулся. Бесконечный цикл.

Исправление — гарантировать advance даже при возврате (0, start):
```swift
// В методе tokenize после вызова readNumber:
let (number, newIndex) = readNumber(cleaned, from: i)
tokens.append(.number(number))
i = newIndex
if i == startIndex {  // не продвинулись — значит символ не может быть началом числа
    advance(&i, in: cleaned)
}
```

Или проще — перед проверкой `if char.isNumber || char == "."` убедиться что "." не начинает число (точка может быть только десятичным разделителем, но не первым символом):

```swift
// Для "." — это не может быть началом числа в математике.
// Но в данном калькуляторе "." одиночная должна, возможно, вызывать ошибку.
```

Лучшее исправление — обрабатывать "." отдельно и возвращать ошибку:
```swift
if char == "." {
    throw CalculatorError.invalidCharacter(".")
}
```
