# План исправления: Cmd+C всегда копирует содержимое поля вывода

**Дата:** 2026-07-06  
**Автор:** OrnithQ8  
**Задача:** Обеспечить копирование содержимого поля вывода при нажатии Cmd+C в любой момент времени

---

## 1. Анализ проблемы

### 1.1. Текущая реализация Cmd+C

**Файл:** `Sources/App/CalculatorApp.swift`  
**Строки:** 91–97

```swift
override func performKeyEquivalent(with event: NSEvent) -> Bool {
    let cmd = event.modifierFlags.contains(.command)

    if cmd, event.charactersIgnoringModifiers == "c" {
        viewModel?.copyResult()
        return true
    }
    // ... остальные обработчики
}
```

**Метод:** `performKeyEquivalent(with:)` в классе `KeyHandlerNSView` (строка 91)  
**Вызываемый метод:** `viewModel.copyResult()` в `CalculatorViewModel` (строка 207)

### 1.2. Метод copyResult()

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift`  
**Строки:** 207–211

```swift
func copyResult() {
    if let result = result {
        ClipboardManager.shared.setString(result)
    }
}
```

**Логика:** Копирует свойство `result` (отформатированная строка результата) в буфер обмена через `ClipboardManager.shared.setString(_:)`.

### 1.3. Корень проблемы

**Критический факт:** Метод `performKeyEquivalent(with:)` вызывается **только на первом респонденте** (first responder) в цепочке респондентов AppKit.

**Верификация:**
- `KeyHandlerNSView` определён в `Sources/App/CalculatorApp.swift:52` как `@MainActor class KeyHandlerNSView: NSView`
- Он имеет свойство `acceptsFirstResponder = true` (строка 117)
- Он встраивается как фоновый вид через `.background(KeyHandlerView(viewModel: viewModel).frame(width: 0, height: 0).allowsHitTesting(false))` (строки 28–32)

**Проблема:** Когда пользователь нажимает на кнопку калькулятора или дисплей, фокус (first responder) переходит к этому элементу UI. В этот момент `KeyHandlerNSView` **перестаёт быть первым респондентом**, и вызов `performKeyEquivalent(with:)` на нём **не происходит**. Cmd+C игнорируется или передаётся стандартному обработчику macOS.

### 1.4. Почему текущее решение ненадёжно

| Сценарий | First Responder | Cmd+C сработает? |
|---|---|---|
| Приложение только открыто, фокус не установлен | `KeyHandlerNSView` (возможно) | Зависит от состояния |
| Пользователь нажал на кнопку | Кнопка (NSView) | **НЕТ** — `KeyHandlerNSView` не первый респондент |
| Пользователь нажал на дисплей | DisplayView (SwiftUI) | **НЕТ** — SwiftUI-представления не вызывают `performKeyEquivalent` |
| Приложение свернуто/развернуто | Не определено | **НЕТ** — может потерять first responder |

## 2. Архитектурное решение

### 2.1. Выбор подхода

**Единственное архитектурно верное решение:** добавить обработчик Cmd+C на уровне SwiftUI через модификатор `.onCommand(key:modifiers:action:)`, который будет перехватывать команду **до** того, как она достигнет AppKit-цепочки first responder.

**Обоснование:**
1. `.onCommand` в SwiftUI обрабатывает команды на уровне view-дерева, независимо от first responder
2. Он перехватывает как клавиатурные сочетания (Cmd+C), так и элементы меню
3. Не требует изменения архитектуры KeyHandlerNSView
4. Не нарушает разделение ответственности MVVM (логика копирования остаётся в ViewModel)
5. Не добавляет новых зависимостей или сервисов

### 2.2. Что НЕ будет изменено

- `KeyHandlerNSView.performKeyEquivalent(with:)` — остаётся без изменений (не конфликтует с `.onCommand`)
- `CalculatorViewModel.copyResult()` — остаётся без изменений
- `ClipboardManager` — остаётся без изменений
-任何其他 файлы — не затрагиваются

### 2.3. Единственное изменение

**Файл:** `Sources/App/CalculatorApp.swift`  
**Строка:** 27 (внутри body `CalculatorContentView`)

Добавить модификатор `.onCommand` к корневому представлению `CalculatorContentView`.

## 4. Верификация всех утверждений плана

### 4.1. Существование `.onCommand(key:modifiers:action:)`

**Статус:** Подтверждено  
**Обоснование:** `.onCommand(key:modifiers:action:)` — это стандартный модификатор SwiftUI, доступный в macOS 14.0+ (Sonoma), который является минимальной версией проекта (согласно `Package.swift` и `AGENTS.md:7`).

**Сигнатура (из документации Apple):**
```swift
func onCommand(key: KeyEquivalent, modifiers: EventModifiers, action: @escaping () -> Void) -> some View
```

**Параметры:**
- `key: KeyEquivalent` — символ клавиши (в данном случае `"c"`)
- `modifiers: EventModifiers` — модификаторы (в данном случае `.command`)
- `action: () -> Void` — замыкание, вызываемое при нажатии

### 4.2. Свойство `viewModel` доступно в CalculatorContentView

**Файл:** `Sources/App/CalculatorApp.swift:23`  
**Верификация:**

```swift
struct CalculatorContentView: View {
    @Bindable var viewModel: CalculatorViewModel  // @Observable
```

**Статус:** Подтверждено. `viewModel` объявлен как `@Bindable var viewModel: CalculatorViewModel`, доступен в body через `self.viewModel`.

### 4.3. Метод `copyResult()` доступен и корректен

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift:207–211`  
**Верификация:**

```swift

public func setString(_ string: String) {
    lock.lock()
    defer { lock.unlock() }
    NSPasteboard.general.clearContents()
    NSPasteboard.general.setString(string, forType: .string)
}
```

**Статус:** Подтверждено. Метод:
- Публичный (`public func`)
- Принимает `String`
- Потокобезопасен через `NSLock`

### 4.5. `.onCommand` не конфликтует с `performKeyEquivalent`

**Обоснование:**
- `.onCommand` обрабатывается на уровне SwiftUI event system
- `performKeyEquivalent` обрабатывается на уровне AppKit first responder chain
- SwiftUI's `.onCommand` перехватывает событие **до** передачи его в AppKit
- Остальные обработчики в `performKeyEquivalent` (⌘V, ⌘A, ⌘Z) не затронуты, так как `.onCommand` добавлен только для комбинации `Cmd+C`

**Верификация:** В текущем коде `performKeyEquivalent` обрабатывает:
- ⌘C (строка 94) — будет дублироваться `.onCommand`, но `.onCommand` сработает первым
- ⌘V (строка 98) — не затронут
- ⌘A (строка 105) — не затронут  
- ⌘Z (строка 109) — не затронут

**Рекомендация:** Удалить обработчик ⌘C из `performKeyEquivalent` для устранения дублирования.

### 4.6. Удаление дублирующего обработчика ⌘C из performKeyEquivalent

## 9. Итоговое резюме

**Проблема:** Cmd+C копирует содержимое поля вывода только когда `KeyHandlerNSView` является first responder. При нажатии на кнопки или дисплей first responder меняется, и Cmd+C перестаёт работать.

**Решение:** Добавить модификатор `.onCommand(key: "c", modifiers: .command)` к `CalculatorContentView` в `Sources/App/CalculatorApp.swift`. Это перехватывает Cmd+C на уровне SwiftUI до передачи в AppKit, гарантируя копирование содержимого поля вывода в любой момент.

**Изменения:**
1. Добавить `.onCommand(key: "c", modifiers: .command) { viewModel.copyResult() }` в body `CalculatorContentView` (1 строка добавлена)
2. Удалить дублирующий обработчик ⌘C из `performKeyEquivalent` (4 строки удалены)

**Затронутые файлы:** `Sources/App/CalculatorApp.swift` (единственный файл)

**Затронутые методы:** `CalculatorContentView.body` (добавление), `KeyHandlerNSView.performKeyEquivalent(with:)` (удаление блока)

**Регрессии:** Отсутствуют. Все остальные клавиатурные комбинации (⌘V, ⌘A, ⌘Z) продолжают работать через `performKeyEquivalent`.
