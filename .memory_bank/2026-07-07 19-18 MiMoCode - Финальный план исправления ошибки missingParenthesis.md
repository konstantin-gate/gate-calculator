**Дата:** 2026-07-07  
**Время:** 19-18  
**Агент:** MiMoCode  
**Статус:** Готов к исполнению  
**Модифицируемый файл:** `Sources/ViewModels/CalculatorViewModel.swift` (1 метод добавляется, 1 метод изменяется)

---

## КРАТКАЯ СВОДКА ПЛАНА (ТЕЗИСЫ)

### Цель исправления
Устранить ошибку `errors.missingParenthesis` ("Пропущена закрывающая скобка"), которая появляется при нажатии кнопки `(` на клавиатуре калькулятора.

### Корень проблемы
Метод `tryAutoEvaluate()` пытается вычислить неполное выражение `"("`, которое не является валидным математическим выражением. Вычислительный движок корректно определяет ошибку и выбрасывает исключение.

### Решение
Добавить проверку незакрытых скобок в метод `tryAutoEvaluate()` перед вызовом вычислительного движка.

### Изменения в коде
1. **Добавить новый метод** `hasUnclosedParentheses(_ expr: String) -> Bool`
2. **Изменить guard-условие** в методе `tryAutoEvaluate()` — добавить проверку `!hasUnclosedParentheses(trimmed)`

### Файл для изменения
`Sources/ViewModels/CalculatorViewModel.swift`

### Объём изменений
- 1 новый метод (~10 строк)
- 1 изменённая строка в guard-условии
- Итого: ~11 строк изменений

### Затронутые компоненты
- **Затронуто:** Только `CalculatorViewModel` (автоматическое вычисление)
- **Не затронуто:** Вычислительный движок (Tokenizer, Parser, Evaluator)
- **Не затронуто:** UI-компоненты (CalculatorView, DisplayView)
- **Не затронуты:** Юнит-тесты (все тесты вызывают `engine.evaluate()` напрямую)

### Поведение после исправления
- При нажатии `(` → символ добавляется, ошибка **НЕ** отображается
- При нажатии `)` после `(` → выражение вычисляется автоматически
- При нажатии `=` при незакрытой скобке → ошибка отображается (корректно)

### Риск регрессий
Минимальный — изменение затрагивает только промежуточное автовычисление, не финальное вычисление по `=`.

## ДЕТАЛЬНЫЙ ПЛАН РЕАЛИЗАЦИИ

### Шаг 1: Добавить приватный метод `hasUnclosedParentheses`

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift`  
**Расположение:** После строки 272 (после метода `isDigitOrDecimal`), перед закрывающей скобкой класса

**Добавляемый код:**

```swift
    /// Проверяет, есть ли в выражении незакрытые открывающие скобки.
    /// Возвращает true, если количество '(' превышает количество ')'.
    private func hasUnclosedParentheses(_ expr: String) -> Bool {
        var count = 0
        for char in expr where char == "(" || char == ")" {
            if char == "(" {
                count += 1
            } else {
                count -= 1
            }
        }
        return count > 0
    }
```

**Верификация сигнатуры:**
- Параметр `expr: String` — тип совпадает со свойством `expression` (CalculatorViewModel.swift:10)
- Возвращаемый тип `Bool` — стандартный Swift тип
- Видимость `private` — совпадает с другими helper-методами в классе (`isDigitOrDecimal`, `isTrailingOperator`, `clearError`)
- Метод не использует внешние зависимости — только локальная переменная `count` и цикл по строке

**Верификация логики метода:**

| Входные данные | `count` после цикла | Возврат | Ожидаемое поведение |
|----------------|---------------------|---------|---------------------|
| `"("` | 1 | `true` | Автовычисление пропущено |
| `"(15+16"` | 1 | `true` | Автовычисление пропущено |
| `"((15+16"` | 2 | `true` | Автовычисление пропущено |
| `"(15+16)"` | 0 | `false` | Автовычисление выполнится |
| `"(15+16)*(2+1)"` | 0 | `false` | Автовычисление выполнится |
| `"((15+16))"` | 0 | `false` | Автовычисление выполнится |
| `")"` | -1 | `false` | Автовычисление выполнится (ошибка `extraClosingParenthesis`) |
| `"15+16)"` | -1 | `false` | Автовычисление выполнится (ошибка `extraClosingParenthesis`) |
| `"15+16"` | 0 | `false` | Автовычисление выполнится |
| `""` | 0 | `false` | Guard на строке 246 отсечёт пустое выражение |

**Почему метод возвращает `false` при `count < 0`:**
- `count < 0` означает наличие лишних закрывающих скобок `)`
- Это ошибка, которую должен обработать вычислительный движок (выбросит `extraClosingParenthesis`)
- Блокировать автовычисление при лишних `)` не нужно — ошибка должна отобразиться пользователю

**Комментарий к методу написан на русском языке** — соответствует AGENTS.md §1 ("В коде: все комментарии и документация пишутся на русском языке").

### Шаг 2: Изменить guard-условие в методе `tryAutoEvaluate()`

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift`  
**Строка для изменения:** 246

**Текущий код (строки 244-255):**

```swift
    private func tryAutoEvaluate() {
        let trimmed = expression.trimmingCharacters(in: .whitespaces)
        guard !trimmed.isEmpty, !isTrailingOperator(expression) else { return }

        do {
            let value = try engine.evaluate(expression)
            result = formatter.format(value)
            resultDecimal = value
        } catch {
            errorMessage = error.localizedDescription
        }
    }
```

**Новый код (строка 246 изменена):**

```swift
    private func tryAutoEvaluate() {
        let trimmed = expression.trimmingCharacters(in: .whitespaces)
        guard !trimmed.isEmpty, !isTrailingOperator(expression), !hasUnclosedParentheses(trimmed) else { return }

        do {
            let value = try engine.evaluate(expression)
            result = formatter.format(value)
            resultDecimal = value
        } catch {
            errorMessage = error.localizedDescription
        }
    }
```

**Изменение:** Добавлено третье условие `!hasUnclosedParentheses(trimmed)` в guard-условие.

**Логика guard-условия (все три условия должны быть true для продолжения):**

| `!trimmed.isEmpty` | `!isTrailingOperator` | `!hasUnclosedParentheses` | Результат |
|--------------------|-----------------------|---------------------------|-----------|
| true | true | true | Продолжить (полное выражение) |
| true | true | false | Вернуться (незакрытая скоба) |
| true | false | true | Вернуться (trailing operator) |
| true | false | false | Вернуться (trailing operator + unclosed paren) |
| false | — | — | Вернуться (пустое выражение) |

#### 3.2. Почему `evaluate()` НЕ затронут

Метод `evaluate()` (CalculatorViewModel.swift:97-116) вызывается **напрямую** по нажатию `=` и **не использует** `tryAutoEvaluate()`:

```swift
func evaluate() {
    clearError()
    let trimmed = expression.trimmingCharacters(in: .whitespaces)
    guard !trimmed.isEmpty else { return }

    do {
        let value = try engine.evaluate(expression)   // ← прямой вызов
        ...
    } catch {
        errorMessage = error.localizedDescription
    }
}
```

Если пользователь введёт `(15+16` и нажмёт `=`, ошибка `missingClosingParenthesis` по-прежнему будет показана — это **корректное поведение**.

#### 3.3. Почему вычислительный движок НЕ затронут

- Метод `hasUnclosedParentheses` добавляется в `CalculatorViewModel`, не в `CalculatorEngine`
- Вычислительный движок продолжает корректно определять невалидные выражения
- При нажатии `=` движок выбросит ошибку `missingClosingParenthesis` — это правильное поведение

#### 3.4. Почему тесты НЕ затронуты

Все юнит-тесты вызывают `engine.evaluate()` напрямую, минуя `tryAutoEvaluate()`:
- `Tests/Unit/TokenizerTests.swift` — через `tokenizer.tokenize()`
- `Tests/Unit/ParserTests.swift` — через `parser.parse()`
- `Tests/Unit/EvaluatorTests.swift` — через `evaluator.evaluate()`
- `Tests/Unit/CalculatorEngineTests.swift` — через `engine.evaluate()`

**Ни один тест не вызывает `CalculatorViewModel.tryAutoEvaluate()` напрямую.**
