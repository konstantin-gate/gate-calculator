## 1. АНАЛИЗ ПРОБЛЕМЫ

### 1.1 Сценарий воспроизведения бага

Пользователь выполняет следующие действия:
1. Вводит выражение `1234-1`
2. Нажимает `=` (или результат вычисляется автоматически)
3. Получает на дисплее: `1,233` (одна тысяча двести тридцать три)
4. Нажимает `*` (умножить)
5. Вводит `10`
6. Нажимает `=`
7. Получает: `12.33` (вместо ожидаемых `12,330`)

### 1.2 Корневой анализ

**Механизм возникновения бага:**

Шаг 1: Вычисление `1234-1`
- `CalculatorEngine.evaluate("1234-1")` возвращает `Decimal(1233)`
- `NumberFormatterService.format(1233)` возвращает строку `"1,233"`
  - `NumberFormatter` настроен с `groupingSeparator = ","` и `decimalSeparator = "."`
  - Для числа 1233 формируется: `"1,233"` (разделитель тысяч — запятая)
- `result = "1,233"` (строковое представление с разделителем тысяч)

Шаг 2: Ввод оператора `*` после результата
- Вызывается `appendCharacter("*")` в `CalculatorViewModel`
- Проверяется условие: `hasResult && isOperator("*")` → `true`
- Выполняется блок (строки 34-41 CalculatorViewModel.swift):

```swift
if let res = result, let dec = Decimal(string: res.replacingOccurrences(of: ",", with: ".")) {
    expression = dec.description
}
```

- `res` = `"1,233"`
- `res.replacingOccurrences(of: ",", with: ".")` = `"1.233"`
- `Decimal(string: "1.233")` = `0.001233` (одна целая две сотых, а не тысяча двести тридцать три!)
- `dec.description` = `"1.233"` (или подобное)
- `expression = "1.233*"`

**КРИТИЧЕСКАЯ ОШИБКА:** Код путает разделитель тысяч (`,`) с десятичным разделителем (`.`). При замене `","` на `"."` число `"1,233"` (1233) превращается в `"1.233"` (1.233).

Шаг 3: Вычисление `1.233 * 10`
- `CalculatorEngine.evaluate("1.233*10")` возвращает `Decimal(12.33)`
- `NumberFormatterService.format(12.33)` возвращает `"12.33"`
- Результат на дисплее: `12.33`

## 2. АРХИТЕКТУРНОЕ РЕШЕНИЕ

### 2.1 Суть решения

**Добавить в `CalculatorViewModel` свойство `lastResultDecimal: Decimal?`, которое будет хранить последний вычисленный результат в типизированном виде (`Decimal`), вместо того чтобы полагаться на строковое представление с последующей конвертацией обратно в `Decimal`.**

### 2.2 Почему это решение единственно верное

1. **Устраняет корневую причину:** Проблема возникает из-за потери информации при конвертации `Decimal → String (с локализацией) → Decimal`. Хранение в `Decimal` исключает эту потерю.

2. **Не требует сложных преобразований:** Не нужно парсить строку, заменять разделители, обрабатывать крайние случаи.

3. **Типобезопасно:** `Decimal` — это точный числовой тип, который не подвержен ошибкам округления при хранении.

4. **Совместимо с архитектурой:** `CalculatorViewModel` уже использует `Decimal` для `memoryValue`. Добавление ещё одного свойства того же типа логично и последовательно.

5. **Не влияет на UI:** `result: String?` остаётся для отображения на дисплее. Новое свойство используется только internally в логике ViewModel.

### 2.3 Что НЕ будет изменено

- `result: String?` — остаётся для отображения на дисплее
- `NumberFormatterService` — не изменяется
- `CalculatorEngine` — не изменяется
- Структура `HistoryEntry` — не изменяется
- UI-компоненты (`DisplayView`, `CalculatorButton`, `CalculatorView`) — не изменяются

## 4. ПРОВЕРКА ВСЕХ ИСПОЛЬЗУЕМЫХ ЭЛЕМЕНТОВ

### 4.1 Свойство `lastResultDecimal`

- **Тип:** `Decimal?` (опциональный Decimal)
- **Объявление:** `private var lastResultDecimal: Decimal? = nil`
- **Доступ:** private (только внутри `CalculatorViewModel`)
- **Подтверждено:** Тип `Decimal` существует в `Foundation`, опциональные свойства поддерживаются в Swift

### 4.2 Метод `Decimal.description`

- **Существует:** Да, это computed property типа `String`
- **Поведение:** Возвращает строковое представление числа с точкой как десятичным разделителем
- **Пример:** `Decimal(1233).description` = `"1233"`, `Decimal(1.5).description` = `"1.5"`
- **Подтверждено:** Это стандартное поведение `Decimal` в Swift

### 4.3 Метод `-val` (унарный минус для Decimal)

- **Существует:** Да, оператор `-` перегружен для `Decimal`
- **Поведение:** Возвращает инвертированное значение
- **Пример:** `-Decimal(1233)` = `Decimal(-1233)`
- **Подтверждено:** Стандартная операция для числовых типов в Swift

### 4.4 Метод `Decimal(string:)`

- **Существует:** Да, initializer типа `Decimal?`
- **Поведение:** Парсит строку в Decimal, возвращает nil если парсинг неудачен
- **Используется:** Только для парсинга выражений в движке, НЕ для конвертации отформатированных строк
- **Подтверждено:** Стандартный initializer в Foundation

## 5. ВАЛИДАЦИЯ ИСПРАВЛЕНИЯ

### 5.1 Сценарий после исправления

**Шаг 1:** Ввод `1234-1` и нажатие `=`
- `engine.evaluate("1234-1")` = `Decimal(1233)`
- `lastResultDecimal = Decimal(1233)`
- `result = "1,233"` (для отображения)
- `expression = ""`

**Шаг 2:** Ввод `*`
- `hasResult` = true, `isOperator("*")` = true
- `if let dec = lastResultDecimal` → `dec = Decimal(1233)`
- `expression = "1233*"` (используется `dec.description` = `"1233"`)
- `result = nil`

**Шаг 3:** Ввод `10`
- `expression = "1233*10"`

**Шаг 4:** Нажатие `=`
- `engine.evaluate("1233*10")` = `Decimal(12330)`
- `formatter.format(12330)` = `"12,330"`
- `result = "12,330"`

**Ожидаемый результат:** `12,330` ✓

### 5.2 Краевые случаи

**Случай 1: Результат с десятичной дробью**
- Выражение: `7/2`
- Результат: `Decimal(3.5)`
- `lastResultDecimal = Decimal(3.5)`
- `result = "3.5"` (formatter с locale en_US)
- Ввод `*2`:
  - `dec = Decimal(3.5)`
  - `expression = "3.5*2"`
  - Результат: `Decimal(7)` → `"7"` ✓

**Случай 2: Очень большое число**
- Выражение: `1000000*1000`
- Результат: `Decimal(1000000000)`
- `lastResultDecimal = Decimal(1000000000)`
- `result = "1,000,000,000"` (с группировкой)
- Ввод `+1`:
  - `dec = Decimal(1000000000)`
  - `expression = "1000000000+1"`
  - Результат: `Decimal(1000000001)` → `"1,000,000,001"` ✓

**Случай 3: Отрицательный результат**
- Выражение: `0-5`
- Результат: `Decimal(-5)`
- `lastResultDecimal = Decimal(-5)`
- `result = "-5"`
- Ввод `*3`:
  - `dec = Decimal(-5)`
  - `expression = "-5*3"`
  - Результат: `Decimal(-15)` → `"-15"` ✓

**Случай 4: Научная нотация**
- Выражение: `1000000000*1000`
- Результат: `Decimal(1e12)`
- `lastResultDecimal = Decimal(1e12)`
- `result` = научная нотация (зависит от formatter)
- Ввод `*2`:
  - `dec = Decimal(1e12)`
  - `expression = "1e12*2"` (или как вернёт description)
  - Проверить что `Decimal.description` для больших чисел корректен

**Проверка Decimal.description для больших чисел:**
- `Decimal(1e12).description` = `"1000000000000"` (полная запись)
- `Decimal(1.5e20).description` = `"150000000000000000000"` (полная запись)
- Это корректно для парсинга в движке ✓

## 10. РИСКИ И МИТИГАЦИЯ

### 10.1 Риск: Изменение поведения `backspace()` после очистки

**Описание:** После нажатия `AC` свойство `lastResultDecimal` становится `nil`. Если пользователь нажмёт `backspace`, метод `clear()` вызовется и останется `nil`.

**Митигация:** Это ожидаемое поведение. После очистки все состояния сбрасываются.

### 10.2 Риск: Потеря результата при авто-вычислении

**Описание:** Метод `tryAutoEvaluate()` устанавливает `result`, но не обновляет `lastResultDecimal`.

**Митигация:** Это корректно. `lastResultDecimal` должен обновляться только при явном вычислении (`evaluate()`) или вставке из буфера. Авто-вычисление не должно сохранять состояние для продолжения вычислений.

### 10.3 Риск: Несоответствие между `result` и `lastResultDecimal`

**Описание:** Если в будущем будет изменена логика форматирования, `result` (String) и `lastResultDecimal` (Decimal) могут рассинхронизироваться.

**Митигация:** Это не проблема, так как `lastResultDecimal` используется только internally. UI всегда отображает `result`. Если нужно продолжить вычисления, используется `lastResultDecimal`.
