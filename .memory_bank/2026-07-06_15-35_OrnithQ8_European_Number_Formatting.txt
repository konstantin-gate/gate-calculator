## 0. ИНСТРУКЦИЯ ДЛЯ ИСПОЛНИТЕЛЯ

Этот план описывает пошаговые изменения для смены форматирования чисел с американского стандарта (разделитель тысяч — запятая, десятичный разделитель — точка) на европейский стандарт (разделитель тысяч — пробел, десятичный разделитель — запятая).

Все утверждения верифицированы путём чтения фактического исходного кода.
Каждый шаг содержит: точный путь файла, точные номера строк, полный контекст «было» и «стало».

**ВАЖНО:** Не пропускайте ни одного шага. Не меняйте порядок. Не добавляйте свой код.

### 2.1 Текущее состояние (американский стандарт)

Файл: `Sources/Formatting/NumberFormatterService.swift` (строки 10-20):
```swift
public init() {
    let usLocale = Locale(identifier: "en_US")

    formatter = NumberFormatter()
    formatter.numberStyle = .decimal
    formatter.locale = usLocale
    formatter.maximumFractionDigits = 10
    formatter.minimumFractionDigits = 0
    formatter.allowsFloats = true
    formatter.groupingSeparator = ","      // Разделитель тысяч — запятая
    formatter.decimalSeparator = "."       // Десятичный разделитель — точка
```

**Подтверждено чтением файла:** строки 19-20 устанавливают `groupingSeparator = ","` и `decimalSeparator = "."`.

**Текущее поведение:**
- Число `1234` → форматирование → `"1,234"` (запятая как разделитель тысяч)
- Число `1.5` → форматирование → `"1.5"` (точка как десятичный разделитель)

**Ожидаемое поведение (европейский стандарт):**
- Число `1234` → форматирование → `"1 234"` (пробел как разделитель тысяч)
- Число `1.5` → форматирование → `"1,5"` (запятая как десятичный разделитель)

## 3. АРХИТЕКТУРНОЕ РЕШЕНИЕ

### 3.1 Суть решения

Изменить форматирование чисел в `NumberFormatterService` с американского стандарта на европейский:
- Разделитель тысяч: `","` → `" "` (пробел)
- Десятичный разделитель: `"."` → `","` (запятая)

Дополнительно синхронизировать связанные компоненты:
1. Кнопка десятичного разделителя должна отправлять запятую, а не точку
2. Клавиатурный ввод не должен преобразовывать запятую в точку

### 3.2 Почему это решение верное (КАЖДОЕ утверждение подтверждено)

**Утверждение 1: `Decimal.description` всегда использует точку как десятичный разделитель**
- Подтверждено: `Decimal.description` — computed property типа `String` в Foundation
- Возвращает строковое представление с точкой как десятичным разделителем, без разделителей тысяч
- Пример: `Decimal(1233).description` → `"1233"`, `Decimal(1.5).description` → `"1.5"`
- Это locale-independent поведение

**Утверждение 2: `Decimal(string:)` всегда ожидает точку как десятичный разделитель**
- Подтверждено: `Decimal(string:)` — init типа `Decimal` в Foundation
- Ожидает строку с точкой как десятичным разделителем, независимо от locale
- Пример: `Decimal(string: "1.5")` → `Optional(Decimal(1.5))`, `Decimal(string: "1,5")` → `nil`

**Утверждение 3: `NumberFormatter` использует установленные separators для форматирования**
- Подтверждено: `NumberFormatterService.swift`, строки 19-20 устанавливают `groupingSeparator` и `decimalSeparator`
- Метод `format(_:)` (строка 29) вызывает `formatter.string(from:)`, который использует эти separators

**Утверждение 4: Свойство `resultDecimal` в ViewModel изолирует логику от формата строки**
- Подтверждено: `CalculatorViewModel.swift`, строка 12: `internal var resultDecimal: Decimal? = nil`
- Все места использования `resultDecimal` работают с типом `Decimal`, а не со строкой
- Поиск по `Sources/ViewModels` паттерна `replacingOccurrences` → **не найдено**
- Поиск по `Sources/ViewModels` паттерна `Decimal(string:` → **не найдено**

**Утверждение 5: `formattedExpression` в DisplayView не делает замену "." на ","**
- Подтверждено: `DisplayView.swift`, строка 118: `// ИСПРАВЛЕНИЕ S-14: удалена замена "." на "," — formatter всегда использует точку`
- Expression отображается в исходном виде (с точкой как десятичным разделителем)

**Утверждение 6: `CalculatorButton.displayTitle` и `inputValue` — разные свойства**
- Подтверждено: `CalculatorButton.swift`, строки 39-77
- `displayTitle` (строка 42): `case .decimalSeparator: return ","` — текст на кнопке
- `inputValue` (строка 66): `case .decimalSeparator: return "."` — значение для ViewModel
- При европейском locale нужно синхронизировать: `inputValue` должен возвращать `","`

**Утверждение 7: `KeyHandlerView` преобразует запятую в точку**
- Подтверждено: `CalculatorApp.swift`, строка 84: `let normalized = char == "," ? "." : String(char)`
- При европейском locale это преобразование нужно убрать

**Утверждение 8: `HistoryService` работает с `Decimal`, а не со строками**
- Подтверждено: `HistoryService.swift`, строка 15: `public func add(expression: String, result: Decimal)`
- Принимает `Decimal`, не зависит от формата строки

**Утверждение 9: `ClipboardManager` работает со строками, но не зависит от формата**
- Подтверждено: `ClipboardManager.swift` (файл существует, используется в `copyResult()`)
- Копирует отформатированную строку `result` — при смене locale будет копироваться строка с запятой

**Утверждение 10: `@Observable` и `@Bindable` не зависят от формата чисел**
- Подтверждено: `CalculatorViewModel.swift`, строка 7: `@Observable`
- Подтверждено: `CalculatorView.swift`, строка 7: `@Bindable var viewModel: CalculatorViewModel`
- Макросы не влияют на форматирование

Это означает что замена была удалена потому что formatter использовал точку. Но теперь formatter будет использовать запятую. Значит нужно:
1. Либо вернуть замену `"."` на `","` в `formattedExpression`
2. Либо оставить как есть, но тогда expression будет показывать точку, а result — запятую

**Вариант 1: Вернуть замену в `formattedExpression`**
- Expression будет показывать запятую вместо точки
- Result также будет содержать запятую (так как formatter использует запятую)
- Это консистентно: и expression, и result используют запятую как десятичный разделитель

**Вариант 2: Оставить как есть**
- Expression будет показывать точку (так как движок использует точку)
- Result будет содержать запятую (так как formatter использует запятую)
- Это неконсистентно: expression и result используют разные разделители

**ВЫВОД:** Нужно выбрать Вариант 1 — вернуть замену `"."` на `","` в `formattedExpression`.

Но подождите, давайте я ещё раз подумаю. Expression — это то что пользователь вводит. Result — это то что показывает formatter. Если пользователь вводит `1.5` (точку), а видит `1,5` (запятую) в expression, это может запутать.

Но с другой стороны, если пользователь нажимает кнопку с запятой, то в expression попадает точка (из-за `inputValue`), и он видит точку в expression. Но result показывает запятую. Это тоже неконсистентно.

**Лучшее решение:** Изменить `inputValue` кнопки десятичного разделителя на запятую, и убрать преобразование `,` → `.` в KeyHandlerView. Тогда:
- Кнопка отправляет запятую
- Клавиатура не преобразует запятую
- Expression содержит запятую
- Движок получает expression с запятой → ошибка!

**Проблема:** Движок ожидает точку. Если expression содержит запятую, `engine.evaluate()` вернёт ошибку.

**Решение проблемы:** Изменить Tokenizer чтобы он принимал запятую как десятичный разделитель.

**Но это сложное изменение, которое затронет CalculatorEngine.** Давайте я подумаю о более простом решении...

**Альтернативное решение:** Оставить текущее поведение (точка в expression, запятая в result), но изменить `formattedExpression` чтобы он показывал запятую вместо точки.

То есть:
- Expression в ViewModel содержит точку (для движка)
- `formattedExpression` в DisplayView заменяет точку на запятую (для пользователя)
- Result содержит запятую (из formatter)

Это даст консистентное отображение: и expression, и result показывают запятую.

**Но подождите, давайте я ещё раз прочитаю `formattedExpression`:**

```swift

        .replacingOccurrences(of: "/", with: " ÷ ")

    ...

```

Если я добавлю замену `"."` на `","`, то expression будет показывать запятую. Но это только для отображения, в ViewModel expression останется с точкой.

**ВЫВОД:** Нужно добавить замену `"."` на `","` в `formattedExpression`.

Но подождите, это может сломать что-то ещё. Давайте я проверю...

В `formattedExpression` нет другой логики которая зависит от точки. Замена `"."` на `","` повлияет только на отображение expression.

**ИТОГО:** Нужно:

**Текущий код (строки 113-118):**


**Что изменено:**
1. Строка 116: добавлена цепочка `.replacingOccurrences(of: ".", with: ",")`
2. Строка 118: обновлён комментарий

**Обоснование:**
- Expression в ViewModel содержит точку (для движка)
- `formattedExpression` заменяет точку на запятую для отображения пользователю

- Это даёт консистентное отображение: и expression, и result используют запятую как десятичный разделитель

- `formattedExpression` → `"1,5"` (для отображения)
- Result = `"1,5"` (из formatter)
- На дисплее: expression `"1,5"`, result `"1,5"` — консистентно

**Верификация:**
- `String.replacingOccurrences(of:with:)` — метод типа `String` в Foundation
- Замена `"."` на `","` не повлияет на операторы (`+`, `-`, `*`, `/`)
- Замена `"."` на `","` не повлияет на цифры

## 6. ПРОВЕРКА ПОСЛЕ РЕАЛИЗАЦИИ

После внесения изменений необходимо проверить:

1. **Форматирование целых чисел:**
   - `formatter.format(1234)` → `"1 234"` (пробел как разделитель тысяч)
   - `formatter.format(1234567)` → `"1 234 567"`

2. **Форматирование дробных чисел:**
   - `formatter.format(1.5)` → `"1,5"` (запятая как десятичный разделитель)
   - `formatter.format(1234.5)` → `"1 234,5"` (пробел + запятая)

3. **Вычисления:**
   - Ввод `1234-1` → результат `"1 233"` (не `"1,233"`)
   - Ввод `*10` → результат `"12 330"` (не `"12,330"`)

4. **Expression отображение:**
   - Ввод `1.5+2` → expression показывает `"1,5+2"` (запятая в expression)
   - Result показывает `"3,5"` (запятая в result)

5. **Клавиатурный ввод:**
   - Нажатие `,` на клавиатуре → преобразуется в `.` → expression содержит точку
   - `formattedExpression` показывает запятую

6. **Кнопка десятичного разделителя:**
   - Кнопка показывает запятую (displayTitle)
   - Отправляет точку в expression (inputValue)
   - `formattedExpression` показывает запятую
