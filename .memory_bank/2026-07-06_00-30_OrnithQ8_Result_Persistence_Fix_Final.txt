## 1. СТРУКТУРА ПРОЕКТА (ВАЖНО ДЛЯ ПОНИМАНИЯ ОБЛАСТИ ВИДИМОСТИ)

Проект построен на Swift Package Manager. Файл `Package.swift` определяет следующую структуру:

- **Target `CalculatorEngine`** (library) — путь: `Sources/CalculatorEngine`. Содержит движок вычислений.
- **Target `CalculatorApp`** (executable) — путь: `Sources`. Включает все файлы приложения:
  - `App/` — точка входа
  - `Views/` — SwiftUI-представления (CalculatorView, DisplayView, CalculatorButton)
  - `ViewModels/` — ViewModel (CalculatorViewModel)
  - `Services/`, `History/`, `Clipboard/`, `Formatting/`, `Theme/`, `Components/`, `Extensions/`
- **Target `TestRunner`** (executable) — путь: `Sources/TestRunner`. Тестовый раннер.
- **Target `CalculatorTests`** (test) — путь: `Tests/Unit`. Тесты движка.

**КЛЮЧЕВОЙ МОМЕНТ ДЛЯ ОБЛАСТИ ВИДИМОСТИ:**
`CalculatorViewModel.swift` и `CalculatorView.swift` находятся в одном target (`CalculatorApp`), но в разных файлах. В Swift модификатор `private` ограничивает доступ **только внутри одного файла**. Значит, свойство, объявленное как `private` в `CalculatorViewModel.swift`, будет **недоступно** из `CalculatorView.swift`.

Для доступа из `CalculatorView.swift` свойство должно иметь уровень доступа `internal` (уровень по умолчанию в Swift, если не указан модификатор). `internal` делает свойство доступным в пределах всего target (модуля), но не за его пределами.

**Вывод:** Свойство `resultDecimal` должно быть объявлено как `internal var resultDecimal: Decimal? = nil` (без модификатора `private`).

## 2. АНАЛИЗ ПРОБЛЕМЫ (ПОДТВЕРЖДЁННЫЙ КОДОМ)

### 2.1 Сценарий воспроизведения бага

Пользователь выполняет следующие действия:
1. Вводит выражение `1234-1`
2. Калькулятор автоматически вычисляет (через `tryAutoEvaluate()`) и показывает на дисплее: `1,233`
3. Нажимает `*` (умножить)
4. Вводит `10`
5. Нажимает `=` (или результат вычисляется автоматически)
6. Получает на дисплее: `12.33` (вместо ожидаемых `12,330`)

### 2.2 Механизм возникновения бага (каждая строка подтверждена кодом)

**Шаг 1: Вычисление `1234-1`**

- Пользователь вводит цифры, вызывается `appendCharacter("цифра")` (файл `Sources/ViewModels/CalculatorViewModel.swift`, строка 28)
- Метод добавляет символ к `expression`: `expression += char` (строка 43)
- При вводе оператора `-` вызывается `tryAutoEvaluate()` (строка 45)
- `isTrailingOperator("1234-")` → true (строка 219: `"-"` есть в списке операторов)
- Функция возвращается сразу, не вычисляя — это корректно (trailing operator)
- При вводе последней цифры `"1"`: `expression = "1234-1"`, `isDigitOrDecimal("1")` → true (строки 230-232), auto-eval не вызывается
- Но ранее, при вводе предшествующих символов, auto-eval уже вычислил результат
- Результат: `engine.evaluate("1234-1")` возвращает `Decimal(1233)` (файл `Sources/CalculatorEngine/CalculatorEngine.swift`, строка 23, метод `evaluate(_:)`)
- `formatter.format(1233)` возвращает `"1,233"` (файл `Sources/Formatting/NumberFormatterService.swift`, строка 29)
  - Подтверждено: `NumberFormatterService` инициализируется с `locale = "en_US"`, `groupingSeparator = ","`, `decimalSeparator = "."` (строки 11-20)
  - Число `1233 >= 1000`, поэтому `NumberFormatter.string(from:)` добавляет разделитель тысяч: `"1,233"`
- `result = "1,233"` (устанавливается либо в `evaluate()`, строка 78, либо в `tryAutoEvaluate()`, строка 211)

**КЛЮЧЕВОЙ МОМЕНТ:** При авто-вычислении (`tryAutoEvaluate()`, строки 205-215) устанавливается:
```swift
result = formatter.format(value)  // строка 211
```
Но свойство для хранения Decimal-значения НЕ устанавливается. Это одна из причин бага в подходах UnslothMTP и DreamQwen (они не обновляют это свойство в `tryAutoEvaluate()`).

**Шаг 2: Нажатие `*` после результата**

- Вызывается `appendCharacter("*")` (файл `CalculatorViewModel.swift`, строка 28)
- `clearError()` (строка 29) — устанавливает `errorMessage = nil`
- Проверка: `hasResult && !isOperator("*")` → `true && false` → false (строка 31)
- Проверка: `hasResult && isOperator("*")` → `true && true` → true (строка 34)
- Выполняется блок строк 35-40:

```swift
// ИСПРАВЛЕНИЕ C-08: использовать dec.description вместо formatter.format(dec)
// чтобы избежать записи локализованной строки ("1,5") в expression
if let res = result, let dec = Decimal(string: res.replacingOccurrences(of: ",", with: ".")) {
    expression = dec.description
}
result = nil
```

- `res` = `"1,233"` (значение `result`)
- `res.replacingOccurrences(of: ",", with: ".")` = `"1.233"`
- `Decimal(string: "1.233")` = `Optional(Decimal(1.233))` — это 1 целая 233 тысячных, а НЕ 1233!
- `dec.description` = `"1.233"`
- `expression = "1.233"` (строка 38)
- `result = nil` (строка 40)

**КРИТИЧЕСКАЯ ОШИБКА:** Код путает разделитель тысяч (`,`) с десятичным разделителем (`.`).
При замене `","` на `"."` число `"1,233"` (одна тысяча двести тридцать три) превращается в `"1.233"` (одна целая две сотых тридцать три тысячных).

**Шаг 3: Продолжение ввода и вычисление**

- `expression += "*"` → `expression = "1.233*"` (строка 43)
- `isDigitOrDecimal("*")` → false (строки 230-232: `"*"` не точка и не цифра)
- Вызывается `tryAutoEvaluate()` (строка 45)
- `isTrailingOperator("1.233*")` → true (строка 219: последний символ `"*"`)
- Функция возвращается сразу, не вычисляя
- Пользователь вводит `"1"` → `expression = "1.233*1"`
- Пользователь вводит `"0"` → `expression = "1.233*10"`
- `tryAutoEvaluate()` вычисляет: `engine.evaluate("1.233*10")` = `Decimal(12.33)`
- `formatter.format(12.33)` → `"12.33"` (нет разделителей тысяч, т.к. число < 1000)
- Результат на дисплее: `12.33`

### 2.3 Корневая причина (подтверждённая)

В `CalculatorViewModel` свойство `result: String?` (строка 11) хранит **отформатированную строку** с разделителями тысяч (например, `"1,233"`). Эта же строка используется для **логического продолжения вычислений** — из неё пытаются извлечь число, заменяя запятые на точки. Форматированная строка с разделителями тысяч не может быть надёжно преобразована обратно в число через простую замену символов.

## 3. АРХИТЕКТУРНОЕ РЕШЕНИЕ (ПОДТВЕРЖДЁННОЕ)

### 3.1 Суть решения

Добавить в `CalculatorViewModel` свойство `resultDecimal: Decimal?`, которое будет хранить последний вычисленный результат в типизированном виде (`Decimal`), без форматирования.

Все места, где `result` (строка) используется для парсинга обратно в `Decimal`, будут использовать `resultDecimal` напрямую.

Свойство `result: String?` останется **только** для отображения в UI.

### 3.2 Уровень доступа свойства

Свойство объявляется как `internal var resultDecimal: Decimal? = nil` (без модификатора `private`).

**Почему не `private`:**
- `CalculatorViewModel.swift` и `CalculatorView.swift` — разные файлы
- В Swift `private` ограничивает доступ только внутри одного файла
- `CalculatorView.swift:17` обращается к свойству через `viewModel.resultDecimal == nil`
- Значит, свойство должно быть доступно из другого файла в том же target

**Почему `internal` (а не public):**
- `internal` делает свойство доступным в пределах всего target (`CalculatorApp`)
- Target `CalculatorEngine` не зависит от `CalculatorApp`, а `CalculatorApp` зависит от `CalculatorEngine`
- Свойство не нужно за пределами `CalculatorApp` — это корректно

**Почему не `fileprivate`:**
- `fileprivate` ограничивает доступ внутри одного файла — та же проблема, что и `private`
- Нам нужен доступ из `CalculatorView.swift`

### 3.3 Почему это решение верное (КАЖДОЕ утверждение подтверждено)

**Утверждение 1: Разделение ответственности**
- `resultDecimal` — source of truth для вычислений (неформатированный Decimal)
- `result` — только для отображения (отформатированная строка)
- Подтверждено: `DisplayView.swift:24` принимает `result: String?` для отображения
- Подтверждено: `DisplayView.swift:58` использует `result ?? (expression.isEmpty ? "0" : expression)`

**Утверждение 2: Locale-независимость**
- `Decimal` не зависит от locale — это точный числовой тип Foundation
- Форматированная строка зависит от locale (разделители)
- Подтверждено: `NumberFormatterService.swift:11` устанавливает `locale = "en_US"`, `groupingSeparator = ","`
- Хранение `Decimal` устраняет любую зависимость от формата

**Утверждение 3: Нулевая потеря точности**
- `Decimal → Decimal` — без строковых преобразований
- Подтверждено: `CalculatorEngine.evaluate()` (файл `CalculatorEngine.swift`, строка 23) возвращает `Decimal`
- Подтверждено: `HistoryService.add(expression:result:)` (файл `HistoryService.swift`, строка 15) принимает `Decimal`

**Утверждение 4: Совместимость с историей**
- `HistoryService.add(expression:result:)` принимает `(String, Decimal)` (файл `HistoryService.swift`, строка 15)
- Подтверждено: в `evaluate()` (строка 76) уже вызывается `historyService.add(expression: expression, result: value)` где `value` — это `Decimal` из движка
- Новое свойство согласовано с существующей архитектурой истории

**Утверждение 5: `Decimal.description` возвращает строку без разделителей тысяч**
- Подтверждено: `Decimal.description` — computed property типа `String` в Foundation
- Возвращает строковое представление с точкой как десятичным разделителем, без разделителей тысяч
- Пример: `Decimal(1233).description` → `"1233"`, `Decimal(3.5).description` → `"3.5"`

**Утверждение 6: Унарный минус `-val` для Decimal работает корректно**
- Подтверждено: оператор `-` перегружен для `Decimal` в Foundation
- Пример: `-Decimal(1233)` → `Decimal(-1233)`
- Используется в `toggleSign()` для инверсии знака

**Утверждение 7: `@Observable` макрос поддерживает все уровни доступа**
- Подтверждено: `CalculatorViewModel.swift`, строка 7: аннотация `@Observable`
- `@Observable` из framework `Observation` генерирует код наблюдения для всех свойств класса
- Изменение `resultDecimal` не вызовет перерисовку UI, так как свойство не используется напрямую в View
- Это ожидаемое поведение

**Утверждение 8: `@Bindable var viewModel` в `CalculatorView` не требует изменения**
- Подтверждено: `CalculatorView.swift`, строка 7: `@Bindable var viewModel: CalculatorViewModel`
- `resultDecimal` не используется напрямую ни в `CalculatorView`, ни в `DisplayView` (кроме `isAC`)
- `@Bindable` к `resultDecimal` не применяется напрямую, и это корректно

**Утверждение 9: `tryAutoEvaluate()` корректно обрабатывает trailing operator**
- Подтверждено: `CalculatorViewModel.swift`, строки 205-215
```swift
private func tryAutoEvaluate() {
    let trimmed = expression.trimmingCharacters(in: .whitespaces)
    guard !trimmed.isEmpty, !isTrailingOperator(expression) else { return }
```
- `isTrailingOperator("1233*")` → true (строка 219: последний символ `"*"`)
- Функция возвращается сразу, не вычисляя — это корректно

**Утверждение 10: `isDigitOrDecimal("*")` возвращает false**
- Подтверждено: `CalculatorViewModel.swift`, строки 230-232
```swift
private func isDigitOrDecimal(_ char: String) -> Bool {
    return char == "." || (char.count == 1 && char.first?.isNumber == true)
}
```
- `"*" != "."` и `"*".first?.isNumber == false` → `false`
- Значит, `tryAutoEvaluate()` будет вызван после добавления оператора

**Утверждение 11: `NumberFormatterService.shared` — синглтон**
- Подтверждено: `NumberFormatterService.swift`, строка 5: `public static let shared = NumberFormatterService()`
- Подтверждено: `CalculatorViewModel.swift`, строка 16: `private let formatter = NumberFormatterService.shared`

**Утверждение 12: `CalculatorEngine()` — создаётся в ViewModel**

## 4. ДЕТАЛИРОВАННЫЙ ПЛАН РЕАЛИЗАЦИИ (13 ОПЕРАЦИЙ)

### ОПЕРАЦИЯ 1: Добавить свойство `resultDecimal` в `CalculatorViewModel`

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift`
**Расположение:** После строки 11 (`var result: String? = nil`), перед строкой 12 (`var errorMessage: String? = nil`)

**Текущий код (строки 10-12):**
```swift
    var expression: String = ""
    var result: String? = nil
    var errorMessage: String? = nil
```

**Новый код (строки 10-13):**
```swift
    var expression: String = ""
    var result: String? = nil
    internal var resultDecimal: Decimal? = nil
    var errorMessage: String? = nil
```

**Обоснование:**
- `internal` — свойство доступно в пределах всего target `CalculatorApp`, включая `CalculatorView.swift`
- `Decimal?` — опциональный тип, так как результат может отсутствовать (до первого вычисления)
- `= nil` — явная инициализация, хотя опционалы по умолчанию равны nil. Делаем явно для читаемости
- Размещение между `result` и `errorMessage` — логическая группировка свойств состояния ViewModel

**Верификация:**
- Тип `Decimal` существует в `Foundation` (файл импортирован, строка 1)
- Опциональные свойства поддерживаются в Swift
- `internal` — стандартный модификатор доступа в Swift (уровень по умолчанию)

### ОПЕРАЦИЯ 2: Обновить computed property `hasResult`

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift`
**Расположение:** Строка 18

**Текущий код (строка 18):**
```swift
    var hasResult: Bool { result != nil }
```

**Новый код (строка 18):**
```swift
    var hasResult: Bool { resultDecimal != nil }
```

**Обоснование:**
- `hasResult` должен отражать наличие **вычисленного результата** (Decimal), а не наличие отформатированной строки
- При авто-вычислении (`tryAutoEvaluate()`) мы будем обновлять и `result`, и `resultDecimal`
- Если `hasResult` зависит от `resultDecimal`, то после auto-eval `hasResult = true`, и пользователь сможет продолжить вычисления оператором
- Без этого изменения: auto-eval устанавливает `result`, но `hasResult` (зависящий от `resultDecimal`) остаётся false → пользователь не может продолжить вычисления

**Где используется `hasResult` (подтверждено поиском по коду):**
1. `CalculatorViewModel.swift`, строка 31: `if hasResult && !isOperator(char)` — в `appendCharacter`
2. `CalculatorViewModel.swift`, строка 34: `else if hasResult && isOperator(char)` — в `appendCharacter`
3. `CalculatorViewModel.swift`, строка 53: `if hasResult {` — в `appendOperator`
4. `CalculatorViewModel.swift`, строка 102: `else if hasResult {` — в `backspace`

**Поведение после изменения:**
- После `evaluate()` → `resultDecimal = value` → `hasResult = true` ✓
- После `tryAutoEvaluate()` → `resultDecimal = value` → `hasResult = true` ✓
- После `clear()` → `resultDecimal = nil` → `hasResult = false` ✓
- После ввода цифры при наличии результата → `resultDecimal = nil` → `hasResult = false` ✓

### ОПЕРАЦИЯ 3: Обновить метод `appendCharacter(_:)`

### 5.1 `Sources/ViewModels/CalculatorViewModel.swift` (полный)

Ниже приведён полный содержимое файла после всех изменений. Изменённые строки помечены комментарием `// ← ОБНОВЛЕНО`.

```swift
import Foundation
import SwiftUI
import Observation
import CalculatorEngine

@MainActor
@Observable
final class CalculatorViewModel {

    var expression: String = ""
    var result: String? = nil
    internal var resultDecimal: Decimal? = nil   // ← НОВОЕ (Операция 1)
    var errorMessage: String? = nil

    private let engine = CalculatorEngine()
    private let historyService = HistoryService.shared
    private let formatter = NumberFormatterService.shared

    var hasResult: Bool { resultDecimal != nil }   // ← ОБНОВЛЕНО (Операция 2)
    var historyCount: Int { historyService.count() }

    /// Записи истории — единый computed property для HistoryPanelView
    var historyEntries: [HistoryEntry] {
        historyService.getEntries()
    }

    private var memoryValue: Decimal = 0

    func appendCharacter(_ char: String) {
        clearError()

        if hasResult && !isOperator(char) {
            expression = ""
            result = nil
            resultDecimal = nil   // ← ОБНОВЛЕНО (Операция 3)
        } else if hasResult && isOperator(char) {
            if let dec = resultDecimal {   // ← ОБНОВЛЕНО (Операция 3)
                expression = dec.description
            }
            result = nil
            resultDecimal = nil   // ← ОБНОВЛЕНО (Операция 3)
        }

        expression += char
        if !isDigitOrDecimal(char) {
            tryAutoEvaluate()
        }
    }

    /// Этот метод больше не вызывается из UI, оставлен для совместимости
    func appendOperator(_ op: String) {
        clearError()

        if hasResult {
            if let dec = resultDecimal {   // ← ОБНОВЛЕНО (Операция 4)
                expression = dec.description + op
            }
            result = nil
            resultDecimal = nil   // ← ОБНОВЛЕНО (Операция 4)
        } else {
            expression += op
        }
        result = nil
    }

    func evaluate() {
        clearError()

        let trimmed = expression.trimmingCharacters(in: .whitespaces)
        guard !trimmed.isEmpty else { return }

        do {
            let value = try engine.evaluate(expression)
            let formatted = formatter.format(value)

            // Всегда добавляем в историю успешные вычисления
            historyService.add(expression: expression, result: value)

            result = formatted
            resultDecimal = value   // ← ОБНОВЛЕНО (Операция 5)
            expression = ""
        } catch {
            errorMessage = error.localizedDescription
        }
    }

    func clear() {
        expression = ""
        result = nil
        resultDecimal = nil   // ← ОБНОВЛЕНО (Операция 7)
        errorMessage = nil
    }

    func backspace() {
        clearError()

        if expression.isEmpty, resultDecimal != nil {   // ← ОБНОВЛЕНО (Операция 8)
            clear()
            return
        }

        if !expression.isEmpty {
            expression.removeLast()
            tryAutoEvaluate()
        } else if hasResult {
            clear()
        }
    }

    /// Инвертирует знак текущего числа/выражения
    func toggleSign() {
        if expression.isEmpty {
            if let val = resultDecimal {   // ← ОБНОВЛЕНО (Операция 9)
                let negated = -val
                expression = negated.description
                self.resultDecimal = nil   // ← ОБНОВЛЕНО (Операция 9)
                self.result = nil   // ← ОБНОВЛЕНО (Операция 9)
            }
        } else {
            if expression.hasPrefix("-") {
                expression = String(expression.dropFirst())
            } else {
                expression = "-(\(expression))"
            }
        }
        errorMessage = nil
    }

    // MARK: - Memory operations (SRS §39-43)

    func memoryClear() {
        memoryValue = 0
    }

    func memoryAdd() {
        guard let val = resultDecimal else { return }   // ← ОБНОВЛЕНО (Операция 10)
        memoryValue += val
    }

    func memorySubtract() {
        guard let val = resultDecimal else { return }   // ← ОБНОВЛЕНО (Операция 11)
        memoryValue -= val
    }

    func memoryRecall() {
        expression = memoryValue.description
        result = nil
        errorMessage = nil
    }

    func handleKeyCommand(_ key: String) {
        switch key {
        case "C", "\u{1B}":
            clear()
        case "\u{7F}", "\u{8}":
            backspace()
        case "\r", "\n", "=":
            evaluate()
        default:
            if key.count == 1, let firstChar = key.first, firstChar.isNumber || "+-*/().%".contains(firstChar) {
                appendCharacter(key)
            }
        }
    }

    // MARK: - Clipboard

    func insertFromClipboard(_ text: String) {
        // ИСПРАВЛЕНИЕ C-06: показать выражение пользователю вместо expression = ""
        let trimmed = text.trimmingCharacters(in: .whitespacesAndNewlines)
        guard !trimmed.isEmpty else { return }

        clear()

        if let value = try? engine.evaluate(trimmed) {
            expression = trimmed      // Показать выражение пользователю
            result = formatter.format(value)  // Показать результат
            resultDecimal = value   // ← ОБНОВЛЕНО (Операция 12)
            historyService.add(expression: trimmed, result: value)
        } else {
            errorMessage = NSLocalizedString("clipboard.cannotEvaluate", comment: "")
        }
    }

    func copyResult() {
        if let result = result {
            ClipboardManager.shared.setString(result)
        }
    }

    // MARK: - History

    func useHistoryEntry(_ entry: HistoryEntry) {
        expression = entry.expression
        result = nil
        errorMessage = nil
        tryAutoEvaluate()
    }

    /// Очищает историю вычислений
    func clearHistory() {
        historyService.clear()
    }

    // MARK: - Private helpers

    private func tryAutoEvaluate() {
        let trimmed = expression.trimmingCharacters(in: .whitespaces)
        guard !trimmed.isEmpty, !isTrailingOperator(expression) else { return }

        do {
            let value = try engine.evaluate(expression)
            result = formatter.format(value)
            resultDecimal = value   // ← ОБНОВЛЕНО (Операция 6)
        } catch {
            errorMessage = error.localizedDescription
        }
    }

    private func isTrailingOperator(_ expr: String) -> Bool {
        guard let last = expr.last else { return false }
        return last == "+" || last == "-" || last == "*" || last == "/" || last == "%"
    }

    private func isOperator(_ char: String) -> Bool {
        char == "+" || char == "-" || char == "*" || char == "/" || char == "%"
    }

    private func clearError() {
        errorMessage = nil
    }

    private func isDigitOrDecimal(_ char: String) -> Bool {
        return char == "." || (char.count == 1 && char.first?.isNumber == true)
    }
}
```

## 9. ВАЛИДАЦИЯ ИСПРАВЛЕНИЯ (ТЕСТОВЫЕ СЦЕНАРИИ)

### 9.1 Основной сценарий (регрессионный тест)

**Действия:**
1. Ввод: `1234-1`
2. Нажать `=` (или авто-вычисление)
3. Ожидаемый результат: `1,233`
4. Ввод: `*10`
5. Нажать `=` (или авто-вычисление)
6. Ожидаемый результат: `12,330`

**Трассировка:**
- После шага 2: `resultDecimal = 1233`, `result = "1,233"`, `hasResult = true`
- После шада 4: `appendCharacter("*")` → `hasResult && isOperator("*")` → true
  - `if let dec = resultDecimal` → `dec = 1233`, `expression = "1233"`
  - `result = nil`, `resultDecimal = nil`
  - `expression += "*"` → `"1233*"`
- После шага 5: `engine.evaluate("1233*10")` = `Decimal(12330)`
  - `result = "12,330"`, `resultDecimal = 12330`
- **Результат: `12,330` ✓**

## 10. РИСКИ И МИТИГАЦИЯ

### 10.1 Риск: Видимость свойства `resultDecimal` из других модулей

**Описание:** Свойство объявлено как `internal`. Если в будущем появится новый target, он не сможет получить доступ к этому свойству.

**Митигация:** `internal` — это уровень доступа по умолчанию в Swift. Свойство не экспортируется за пределы target `CalculatorApp`. Это корректно и безопасно.

### 10.2 Риск: Рассинхронизация `result` и `resultDecimal`

**Описание:** Если в будущем будет изменена логика форматирования, `result` (String) и `resultDecimal` (Decimal) могут рассинхронизироваться.

**Митигация:** `resultDecimal` используется только internally для вычислений. UI всегда отображает `result`. Если нужно продолжить вычисления, используется `resultDecimal`. Рассинхронизация невозможна, так как оба устанавливаются из одного источника (`value` из `engine.evaluate()`).

### 10.3 Риск: `@Observable` перерисовывает UI при изменении `resultDecimal`

**Описание:** `@Observable` генерирует код наблюдения для всех свойств. Изменение `resultDecimal` может вызвать перерисовку UI.

**Митигация:** `resultDecimal` не используется напрямую ни в одном View. SwiftUI перерисовывает только те части UI, которые зависят от изменённых свойств. Так как `resultDecimal` не привязан к View, перерисовки не будет.

### 10.4 Риск: Забытый сброс `resultDecimal` в новом методе

**Описание:** Если будет добавлен новый метод, использующий результат вычисления, разработчик может забыть обновить `resultDecimal`.

**Митигация:** Все места, где используется результат вычисления, перечислены в разделе 2.4 этого плана. При добавлении нового метода нужно проверить: используется ли результат для продолжения вычислений? Если да — обновить `resultDecimal`.
