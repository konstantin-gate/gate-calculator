# План исправления: копирование текущего значения дисплея в буфер обмена

**Дата:** 2026-07-06
**Автор:** MimoCode
**Проблема:** При нажатии ⌘C копируется только отформатированный результат (`result`). Если на дисплее отображается выражение, ошибка или "0" — ничего не копируется.

---

## 1. Анализ проблемы

### 1.1. Текущее поведение метода `copyResult()`

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift:207-211`

```swift
func copyResult() {
    if let result = result {
        ClipboardManager.shared.setString(result)
    }
}
```

**Проблема:** Копирование выполняется **только** если `result != nil`. Свойство `result` устанавливается исключительно в методе `evaluate()` (строка 100), поэтому:
- При вводе выражения (пока не нажат `=`) — `result == nil`, копирования не происходит
- При ошибке — `errorMessage != nil`, но `result == nil`, копирования не происходит
- При пустом дисплее — `result == nil` и `expression.isEmpty == true`, копирования не происходит

### 1.2. Логика отображения на дисплее

**Файл:** `Sources/Views/DisplayView.swift:30-77`

Главное поле вывода определяется строкой 58:
```swift
let mainText = result ?? (expression.isEmpty ? "0" : expression)
```

Полная логика отображения (с учётом ошибки, строки 31-32):

| Состояние | `errorMessage` | `result` | `expression` | Отображается |
|---|---|---|---|---|
| Ошибка | `String` | `nil` | `""` | `errorMessage` (красный текст) |
| Есть результат | `nil` | `String` | `""` | `result` |
| Ввод выражения | `nil` | `nil` | `String` | `expression` |
| Пустой дисплей | `nil` | `nil` | `""` | `"0"` |

### 1.3. Вызов `copyResult()` из UI

**Файл:** `Sources/App/CalculatorApp.swift:91-97`

```swift
override func performKeyEquivalent(with event: NSEvent) -> Bool {
    let cmd = event.modifierFlags.contains(.command)

    if cmd, event.charactersIgnoringModifiers == "c" {
        viewModel?.copyResult()
        return true
    }
```

Cmd+C перехватывается в `performKeyEquivalent` и вызывает `viewModel?.copyResult()`.

### 1.4. Ожидаемое поведение

При нажатии ⌘C **всегда** должно копироваться то, что сейчас отображается в **главном поле вывода** дисплея:

| Состояние дисплея | Копируемое значение |
|---|---|
| Ошибка | Текст ошибки |
| Есть результат | Отформатированный результат |
| Ввод выражения | Текст выражения (ASCII) |
| Пустой дисплей | `"0"` |

**Примечание:** При копировании выражения копируется **сырой текст** (ASCII, например `15+16`), а не форматированное отображение (например `15 ÷ 16`). Это необходимо для корректной вставки обратно через ⌘V.

## 2. Архитектурное решение

Единственное верное решение — **добавить computed property `displayValue`** в `CalculatorViewModel`, которое возвращает точную строку, отображаемую на дисплее. Метод `copyResult()` должен вызывать `displayValue` вместо обращения к `result`.

### 2.1. Почему не другие варианты

**Почему не дублировать логику отображения из DisplayView:**
- DisplayView — это View-слой. ViewModel не должен знать о визуальном форматировании (шрифты, цвета, анимации). Логика отображения в DisplayView включает `.replacingOccurrences(of: "/", with: " ÷ ")` и другие замены символов — это **визуальное** представление, не данные.
- Дублирование логики приведёт к рассинхронизации при изменении отображения.

**Почему не передавать значение из View в ViewModel:**
- Архитектура MVVM запрещает прямую зависимость ViewModel от View.
- `@Observable` framework не предполагает обратную передачу данных из View в ViewModel для каждого действия.

**Почему `displayValue` — правильное решение:**
- Computed property определяет **один источник истины** для "что сейчас показано на дисплее".
- DisplayView уже содержит логику `result ?? (expression.isEmpty ? "0" : expression)` (строка 58). Новая computed property дублирует эту логику **в ViewModel**, что является стандартным MVVM-паттерном (business logic в ViewModel, отображение в View).

## 3. Пошаговый план реализации

### Шаг 1. Добавить computed property `displayValue` в CalculatorViewModel

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift`

**Вставка:** После строки 19 (после computed property `hasResult`), перед строкой 20 (`historyCount`).

**Добавляемый код:**

```swift
/// Текущее значение, отображаемое в главном поле дисплея.
/// Используется для копирования в буфер обмена (⌘C).
var displayValue: String {
    if let error = errorMessage {
        return error
    }
    if let res = result {
        return res
    }
    if !expression.isEmpty {
        return expression
    }
    return "0"
}
```

**Верификация:**
- Тип возвращаемого значения: `String` (не optional) — гарантированно возвращает непустую строку
- Не зависит от View-слоя
- Не использует `NSLock` (не нарушает правило 6.2)
- Помечен как `var` (computed property) — консистентно с `hasResult` (строка 19)

### Шаг 2. Изменить метод `copyResult()`

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift`

**Замена:** Строки 207-211

**Было:**
```swift
func copyResult() {
    if let result = result {
        ClipboardManager.shared.setString(result)
    }
}
```

**Стало:**
```swift
func copyResult() {
    ClipboardManager.shared.setString(displayValue)
}
```

**Верификация:**
- `displayValue` гарантированно возвращает `String` (не optional) — `if let` больше не нужен
- `ClipboardManager.shared.setString(_:)` принимает `String` (не optional) — `ClipboardManager.swift:26`
- Вызов консистентен: `displayValue` (String) → `setString(String)`
