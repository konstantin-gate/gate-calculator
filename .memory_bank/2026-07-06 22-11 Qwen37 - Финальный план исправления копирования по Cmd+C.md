**Дата:** 2026-07-06  
**Автор:** Qwen36  
**Задача:** Обеспечить копирование содержимого поля вывода при нажатии ⌘C в любой момент времени  
**Основа:** Синтез планов OrnithQ8 и MimoCode с устранением всех недостатков

## ЧАСТЬ 1. ТЕЗИСНЫЙ ПЛАН

### Проблема (два независимых аспекта)

1. **Что копировать:** `copyResult()` копирует только `result`, игнорируя expression / error / "0".
2. **Где перехватывать:** `performKeyEquivalent` на `KeyHandlerNSView` не срабатывает, когда он не является first responder.

### Решение

1. Добавить computed property `displayValue` в `CalculatorViewModel` — единый источник истины для «что сейчас на дисплее».
2. Добавить `.onKeyPress(key: "c", modifiers: .command)` на `CalculatorContentView` — перехват ⌘C на уровне SwiftUI, независимо от first responder.

### Изменения

| Файл | Тип | Описание |
|---|---|---|
| `Sources/ViewModels/CalculatorViewModel.swift` | Вставка + Замена | Добавить `displayValue` (после строки 19), изменить `copyResult()` (строки 207–211) |
| `Sources/App/CalculatorApp.swift` | Вставка | Добавить `.onKeyPress` (после строки 32) |

### Порядок действий

1. Изменить `CalculatorViewModel.swift`: вставить `displayValue`, заменить `copyResult()`.
2. Изменить `CalculatorApp.swift`: вставить `.onKeyPress` в `CalculatorContentView.body`.

### Что НЕ будет изменено

- `KeyHandlerNSView.performKeyEquivalent` — ⌘C остаётся как fallback
- `ClipboardManager` — без изменений
- `DisplayView` — без изменений
- Обработчики ⌘V, ⌘A, ⌘Z — без изменений
- Все остальные файлы проекта — без изменений

### 1. Анализ проблемы

#### 1.1. Аспект 1: `copyResult()` копирует не то, что на дисплее

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift:207-211`

```swift
func copyResult() {
    if let result = result {
        ClipboardManager.shared.setString(result)
    }
}
```

**Проблема:** Копирование выполняется **только** если `result != nil`. Свойство `result` устанавливается исключительно в `evaluate()` (строка 100) и `tryAutoEvaluate()` (строка 235).

**Сценарии, когда копирование не происходит:**

| Состояние | `result` | Копирует? |
|---|---|---|
| Ввод выражения (до автовычисления) | `nil` | НЕТ |
| Ошибка | `nil` | НЕТ |
| Пустой дисплей | `nil` | НЕТ |
| Есть результат | `String` | ДА |
| Автовычисление (ввод оператора) | `String` | ДА |

#### 1.2. Аспект 2: `performKeyEquivalent` зависит от first responder

**Файл:** `Sources/App/CalculatorApp.swift:91-97`

```swift
override func performKeyEquivalent(with event: NSEvent) -> Bool {
    let cmd = event.modifierFlags.contains(.command)
    if cmd, event.charactersIgnoringModifiers == "c" {
        viewModel?.copyResult()
        return true
    }
    // ...
}
```

**Проблема:** `performKeyEquivalent` вызывается **только** на first responder в цепочке респондентов AppKit. Когда пользователь кликает на кнопку калькулятора, фокус может перейти к SwiftUI Button, и `KeyHandlerNSView` перестаёт быть first responder.

**Верификация:**
- `KeyHandlerNSView` определён в `Sources/App/CalculatorApp.swift:52` как `@MainActor class KeyHandlerNSView: NSView`
- `acceptsFirstResponder = true` — подтверждено в `CalculatorApp.swift:117`
- Он встраивается как фоновый вид через `.background(KeyHandlerView(viewModel: viewModel).frame(width: 0, height: 0).allowsHitTesting(false))` — подтверждено в `CalculatorApp.swift:28-32`

#### 1.3. Логика отображения на дисплее

**Файл:** `Sources/Views/DisplayView.swift:30-58`

| Состояние | `errorMessage` | `result` | `expression` | Отображается |
|---|---|---|---|---|
| Ошибка | `String` | `nil` | `String` (не сброшен) | `errorMessage` |
| Есть результат | `nil` | `String` | `""` | `result` |
| Автовычисление | `nil` | `String` | `String` | `result` (строка выражения скрыта) |
| Ввод выражения | `nil` | `nil` | `String` | `expression` |
| Пустой дисплей | `nil` | `nil` | `""` | `"0"` |

**Верификация строки 58:** `let mainText = result ?? (expression.isEmpty ? "0" : expression)` — подтверждено в `DisplayView.swift:58`.

**Верификация строки 17:** `if !expression.isEmpty && result == nil && errorMessage == nil` — строка выражения показывается только когда `result == nil` и `errorMessage == nil`. Подтверждено в `DisplayView.swift:17`.

### 2. Архитектурное решение

#### 2.1. Выбор подхода

**Для аспекта 1 («что копировать»):**  
Добавить computed property `displayValue` в `CalculatorViewModel`. Это стандартный MVVM-паттерн — ViewModel предоставляет данные для отображения.

**Для аспекта 2 («где перехватывать»):**  
Добавить `.onKeyPress(key: "c", modifiers: .command)` на `CalculatorContentView`. Это перехватывает ⌘C на уровне SwiftUI view-дерева, независимо от first responder.

**Почему `.onKeyPress`, а не `.onCommand`:**
- `.onCommand(key:modifiers:action:)` **НЕ СУЩЕСТВУЕТ** в SwiftUI API. Это была ошибка в плане OrnithQ8.
- `.onKeyPress(key:modifiers:action:)` — реальный API, доступный в macOS 14.0+.
- Сигнатура: `func onKeyPress(key: KeyEquivalent, modifiers: EventModifiers = [], action: @escaping () -> KeyPress.Result) -> some View`

**Почему не удалять ⌘C из `performKeyEquivalent`:**
- `.onKeyPress` и `performKeyEquivalent` работают на одном уровне (AppKit responder chain).
- Когда `KeyHandlerNSView` — first responder: его `performKeyEquivalent` срабатывает первым и возвращает `true`, `.onKeyPress` **НЕ** срабатывает.
- Когда `KeyHandlerNSView` НЕ first responder: `performKeyEquivalent` не вызывается на нём, `.onKeyPress` срабатывает.
- **Нет дублирования** — каждый механизм работает в своём сценарии.
- `performKeyEquivalent` остаётся как fallback для максимальной надёжности.

**Почему `.onKeyPress` работает независимо от first responder:**
- `.onKeyPress` в SwiftUI macOS использует `performKeyEquivalent` под капотом.
- SwiftUI добавляет свой `performKeyEquivalent` на NSView, связанный с view-деревом.
- Этот NSView является родителем `KeyHandlerNSView` в responder chain.
- Если `KeyHandlerNSView` — first responder и его `performKeyEquivalent` возвращает `true`, событие обработано, и `.onKeyPress` на родительском view НЕ срабатывает.
- Если `KeyHandlerNSView` НЕ first responder, событие проходит через responder chain и достигает SwiftUI NSView, где `.onKeyPress` срабатывает.

#### 2.2. Что НЕ будет изменено

| Компонент | Статус |
|---|---|
| `KeyHandlerNSView.performKeyEquivalent` | ⌘C остаётся (fallback) |
| `ClipboardManager.setString(_:)` | Без изменений |
| `DisplayView` | Без изменений (у него своя логика отображения: `formattedExpression`, адаптивный шрифт, анимации) |
| Обработчики ⌘V, ⌘A, ⌘Z | Без изменений |
| Все другие файлы проекта | Без изменений |

**Важно:** `displayValue` НЕ должен использоваться в `DisplayView` для отображения. У `DisplayView` есть собственная логика визуального форматирования (`formattedExpression`, адаптивный шрифт, анимации). `displayValue` предназначен **только** для копирования в буфер обмена.

#### Шаг 1: Добавить computed property `displayValue` в `CalculatorViewModel`

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift`

**Место вставки:** После строки 19 (`var hasResult: Bool { resultDecimal != nil }`), перед строкой 20 (`var historyCount: Int { historyService.count() }`).

**Добавляемый код:**

```swift

    /// Используется для копирования в буфер обмена (⌘C).
    /// Возвращает сырой текст (ASCII), без визуального форматирования.
    var displayValue: String {
        if let error = errorMessage {
            return error
        }
        if let res = result {
            return res
        }
        if !expression.isEmpty {
            return expression
        }
        return "0"
    }
```

**Верификация логики:**
- `errorMessage: String?` — подтверждено в `CalculatorViewModel.swift:13`
- `result: String?` — подтверждено в `CalculatorViewModel.swift:11`
- `expression: String` — подтверждено в `CalculatorViewModel.swift:10`

- Возвращает сырой `expression` (не `formattedExpression`) — корректно для вставки через ⌘V

**Верификация видимости:**
- `var displayValue` — без модификатора доступа, по умолчанию `internal`
- Доступен в том же модуле (`CalculatorApp`) — корректно

**Верификация потокобезопасности:**
- `CalculatorViewModel` помечен `@MainActor` — подтверждено в `CalculatorViewModel.swift:6`

- `displayValue` — computed property, читает `@Observable` stored properties
- Observation framework автоматически отслеживает чтение stored properties внутри computed property
- SwiftUI view, использующий `displayValue`, будет обновляться при изменении `errorMessage`, `result` или `expression`

```swift
        let cmd = event.modifierFlags.contains(.command)

        if cmd, event.charactersIgnoringModifiers == "c" {
            viewModel?.copyResult()
            return true
        }
        if cmd, event.charactersIgnoringModifiers == "v" {
            if let text = ClipboardManager.shared.getString() {
                viewModel?.insertFromClipboard(text)
            }
            return true
        }
        // ИСПРАВЛЕНИЕ S-10: ⌘A и ⌘Z
        if cmd, event.charactersIgnoringModifiers == "a" {
            // Select All — в контексте калькулятора заглушка
            return true
        }
        if cmd, event.charactersIgnoringModifiers == "z" {
            // Undo — заглушка (может быть реализовано в будущем)
            return false
        }

        return super.performKeyEquivalent(with: event)
    }
```

| ⌘C (копирование выражения) | Нет — `displayValue` возвращает `expression` когда `result == nil` | Ввести `15+16` (до автовычисления), ⌘C → в буфере `"15+16"` |
| ⌘C (копирование ошибки) | Нет — `displayValue` возвращает `errorMessage` когда он есть | Вызвать ошибку `1/0=`, ⌘C → в буфере текст ошибки |
| ⌘C (пустой дисплей) | Нет — `displayValue` возвращает `"0"` | Очистить (Escape), ⌘C → в буфере `"0"` |
| ⌘C (автовычисление) | Нет — `displayValue` возвращает `result` при автовычислении | Ввести `15+1`, ⌘C → в буфере `"16"` (отображается результат) |
| ⌘V (вставка) | Нет — `performKeyEquivalent` не изменён | Вставить выражение после копирования |
| ⌘A, ⌘Z | Нет — `performKeyEquivalent` не изменён | Проверить заглушки |
| Клавиатурный ввод | Нет — `keyDown` не изменён | Ввести выражение с клавиатуры |
| История | Нет — `useHistoryEntry` не затронут | Загрузить запись из истории, ⌘C |
| Память (MC/M+/M−/MR) | Нет — memory-методы не затронуты | Проверить операции памяти |
| Потеря фокуса | Нет — `.onKeyPress` перехватывает ⌘C | Кликнуть на кнопку, ⌘C → копирование срабатывает |
