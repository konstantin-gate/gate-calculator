# План исправления: MR затирает выражение с оператором

**Дата:** 2026-07-06  
**Автор:** OrnithQ8  
**Задача:** Исправить поведение `memoryRecall()` — при наличии оператора в конце expression значение из памяти затирает выражение вместо добавления после оператора.

---

## Краткое резюме плана (позиции)

1. **Файл для изменения:** `Sources/ViewModels/CalculatorViewModel.swift`
2. **Единственный изменяемый метод:** `memoryRecall()` (строки 176–181)
3. **Суть бага:** `memoryRecall()` без условий присваивает `expression = memoryValue.description`, полностью затирая предыдущее выражение, включая оператор в конце
4. **Архитектурное решение:** Добавить проверку: если expression не пуст и заканчивается оператором — добавить значение памяти ПОСЛЕ оператора (через `+=`), а не заменять выражение целиком
5. **Используемый существующий метод:** `isOperator(_ char: String)` (строка 255) — private, внутри класса, верифицирован
6. **Свойство `memoryValue`** (строка 37) — private, тип `Decimal`, `.description` возвращает ASCII-строку без разделителей тысяч
7. **Свойство `expression`** (строка 10) — public var, String
8. **Свойства `result`, `resultDecimal`, `errorMessage`** — сбрасываются в nil (без изменений)
9. **Файл `CalculatorView.swift`** — НЕ изменяется (маппинг `.mR → memoryRecall()` корректен)
10. **Файлы движка, сервисов, Views** — НЕ изменяются
11. **Побочных эффектов нет:** изменение локализовано в одном методе одного файла
12. **Регрессионный анализ:** изменение не затрагивает `memoryAdd`, `memorySubtract`, `memoryClear`, `appendCharacter`, `evaluate`
13. **Верификация:** каждый вызов и свойство подтверждены прямым чтением файла `CalculatorViewModel.swift`

## Детализированный план реализации

### 0. Предварительный анализ бага (верифицирован)

**Сценарий воспроизведения:**
1. Набрать "10" → expression = `"10"`
2. Нажать M+ → `memoryAdd()` → `currentDisplayValue` вычисляет expression `"10"` → Decimal(10) → memoryValue = 10
3. Нажать "+" → `appendCharacter("+")` → hasResult = false → expression += "+" → expression = `"10+"` → `tryAutoEvaluate()` → `isTrailingOperator("10+")` = true → возврат без вычисления
4. Нажать MR → `memoryRecall()` → expression = memoryValue.description = `"10"` → result = nil, resultDecimal = nil, errorMessage = nil
5. Нажать "=" → `evaluate()` → expression = `"10"` → engine.evaluate("10") = 10 → result = "10"

**Результат:** 10 (ожидалось 20)

**Корневая причина:** `memoryRecall()` (строки 176–181) не учитывает наличие оператора в конце expression. Метод безусловно присваивает `expression = memoryValue.description`, полностью затирая предыдущее состояние.

### 1. Изменение: метод `memoryRecall()` в `CalculatorViewModel.swift`

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift`  
**Метод:** `memoryRecall()` (строки 176–181)  
**Текущий код:**

```swift
func memoryRecall() {
    expression = memoryValue.description
    result = nil
    resultDecimal = nil
    errorMessage = nil
}
```

**Новый код:**

```swift
func memoryRecall() {
    if !expression.isEmpty, isOperatorLastChar(expression) {
        expression += memoryValue.description
    } else {
        expression = memoryValue.description
    }
    result = nil
    resultDecimal = nil
    errorMessage = nil
}
```

**Объяснение логики:**
- Если expression не пустая И последний символ — оператор → добавляем значение памяти ПОСЛЕ оператора (строка `expression += memoryValue.description`)
- Во всех остальных случаях — заменяем expression значением из памяти (старое поведение)

### 4. Проверка: `isOperatorLastChar` использует корректный метод

**Утверждение:** Новый метод `isOperatorLastChar(_ expr: String)` вызывает существующий `isOperator(_ char: String)`.

**Верификация:**
- `isOperator` определён в том же классе (`CalculatorViewModel`)
- Видимость `private` — доступен всем методам класса, включая новые приватные методы
- Сигнатура `isOperator(_ char: String) -> Bool` — принимает один параметр типа `String`, возвращает `Bool`
- Вызов `isOperator(last)` где `last: Character` — **НЕ СОВПАДАЕТ** с сигнатурой, принимающей `String`

**ВАЖНОЕ ЗАМЕЧАНИЕ:** `expr.last` возвращает `Character?`, а не `String`. Метод `isOperator` принимает `String`. Необходимо преобразовать Character в String.

**Исправление `isOperatorLastChar`:**

```swift
private func isOperatorLastChar(_ expr: String) -> Bool {
    guard let last = expr.last else { return false }
    return isOperator(String(last))
}
```

**Верификация `String(Character)`:** Конвертация `Character` → `String` через инициализатор `String(_:)` — стандартный Swift-паттерн, типизирован корректно.

### 6. Трассировка граничных случаев

#### 6.1. Expression пуста, есть память
- expression = `""`, memoryValue = 42
- Условие: `!expression.isEmpty` → false → ветка else
- expression = `"42"` ✅ (старое поведение)

#### 6.2. Expression не пуста, последний символ — не оператор
- expression = `"10+5"`, memoryValue = 3
- Условие: last = "5", isOperator("5") = false → ветка else
- expression = `"3"` ✅ (старое поведение — пользователь начинает заново)

#### 6.3. Expression содержит только оператор
- expression = `"+"`, memoryValue = 7
- Условие: не пуст, last = "+", isOperator("+") = true → `expression += "7"`
- expression = `"+7"` — корректно, Tokenizer обработает как унарный минус/число

#### 6.4. Несколько операторов в конце (теоретический кейс)
- expression = `"5++"`, memoryValue = 3
- Условие: last = "+", isOperator("+") = true → `expression += "3"`
- expression = `"5++3"` — Tokenizer/Parser вернут ошибку doubleOperator, что корректно

#### 6.5. MR после evaluate (есть результат)
- expression = `""`, resultDecimal = 25, memoryValue = 10
- Условие: expression пуст → ветка else
- expression = `"10"`, result = nil, resultDecimal = nil ✅ (старое поведение)

#### 6.6. MR → оператор → цифры
- expression = `"10+"`, memoryValue = 5
- MR: expression = `"10+5"`
- "+" → appendCharacter("+): hasResult = false, не оператор → expression += "+" → `"10+5+"`
- "3" → appendCharacter("3"): hasResult = false, digit → expression += "3" → `"10+5+3"`
- "=" → evaluate: 10+5+3 = 18 ✅
