## Описание проблемы

Пользователь сообщает о четырёх ошибках при вводе выражений:

| № | Ввод | Метод ввода | Ожидаемый результат | Фактический результат |
|---|---|---|---|---|
| 1 | `5*-3` | Клавиатура + Enter | `-15` | `"Invalid expression"` |
| 2 | `5*-3` | Cmd+V (вставка) | `-15` | `"clipboard.cannotEvaluate"` |
| 3 | `5*(-3)` | Клавиатура (при вводе `)`) | `-15` | `"errors.doubleOperator"` |
| 4 | `5*(-3)` | Cmd+V (вставка) | `-15` | `"clipboard.cannotEvaluate"` |

## Корневые причины (2 дефекта)

### Дефект A: `validateTokenSequence` отвергает `)` после унарного минуса

**Файл:** `Sources/CalculatorEngine/Tokenizer/Tokenizer.swift:357-361`

**Верифицированный код (read, строка 357-361):**
```swift
case .rightParenthesis:
    let prevIsOp = i > tokens.startIndex && isOperatorOrLeftParen(tokens[i - 1])
    if prevIsOp {
        throw CalculatorError.doubleOperator
    }
```

**Проблема:** Функция `isOperatorOrLeftParen` (строка 369-376) возвращает `true` для `.unaryMinus`. Поэтому последовательность `unaryMinus → rightParenthesis` отвергается как двойной оператор. Это блокирует корректные выражения вида `5*(-3)`, `-(3+5)`, `-3)` и т.д.

**Верификация `isOperatorOrLeftParen` (строка 369-376):**
```swift
private func isOperatorOrLeftParen(_ token: Token) -> Bool {
    switch token {
    case .binaryOperator, .unaryMinus, .leftParenthesis:
        return true
    default:
        return false
    }
}
```

**Влияние:** Дефект A блокирует оба варианта ввода выражения `5*(-3)` — и клавиатурный (при вводе `)`), и через буфер обмена.

### Дефект B: `tryAutoEvaluate` показывает ошибки для неполных выражений при вводе

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift:244-255`

**Верифицированный код (read, строка 244-255):**
```swift
private func tryAutoEvaluate() {
    let trimmed = expression.trimmingCharacters(in: .whitespaces)
    guard !trimmed.isEmpty, !isTrailingOperator(expression), !hasUnclosedParentheses(trimmed) else { return }

    do {
        let value = try engine.evaluate(expression)
        result = formatter.format(value)
        resultDecimal = value
    } catch {
        errorMessage = error.localizedDescription   // ← ПРОБЛЕМА
    }
}
```

**Проблема:** Метод `tryAutoEvaluate()` вызывается из `appendCharacter()` (строка 76-78) после каждого нечислового символа. Если движок выбрасывает ошибку для промежуточного выражения, `errorMessage` устанавливается и отображается на экране. Хотя ошибка очищается при следующем вводе (`clearError()` в начале `appendCharacter`), пользователь видит кратковременное появление ошибки.

**Цепочка вызовов (верифицировано через read):**
1. `CalculatorView.handleButtonPress` (строка 131-165) → `viewModel.appendCharacter(label.inputValue)`
2. `CalculatorViewModel.appendCharacter` (строка 60-79) → `tryAutoEvaluate()` (строка 76-78)
3. `tryAutoEvaluate` (строка 244-255) → `engine.evaluate(expression)` → при ошибке: `errorMessage = error.localizedDescription`

**Влияние:** Дефект B вызывает мелькание ошибок при наборе выражений, содержащих унарный минус после оператора (например, при вводе символа `-` в выражении `5*-`).

## Архитектурно верное решение

### Исправление 1: Модификация `validateTokenSequence` (Дефект A)

**Файл:** `Sources/CalculatorEngine/Tokenizer/Tokenizer.swift`  
**Метод:** `validateTokenSequence(_:)` (строка 324)  
**Точка изменения:** строка 357-361

**Текущий код:**
```swift
case .rightParenthesis:
    let prevIsOp = i > tokens.startIndex && isOperatorOrLeftParen(tokens[i - 1])
    if prevIsOp {
        throw CalculatorError.doubleOperator
    }
```

**Новый код:**
```swift
case .rightParenthesis:
    let prevToken = i > tokens.startIndex ? tokens[i - 1] : nil
    let isInvalidPrev: Bool = {
        guard let prev = prevToken else { return false }
        if case .binaryOperator = prev { return true }
        if case .leftParenthesis = prev { return true }
        return false
    }()
    if isInvalidPrev {
        throw CalculatorError.doubleOperator
    }
```

**Логика:** `)` после унарного минуса — допустимо (например, `-3)`, `5*(-3)`). `)` после бинарного оператора или `(` — недопустимо (например, `5+3)`, `5(-3)`).

**Верификация совместимости:**
- `5+3)` → tokens: [5, +, 3, )] → `prevToken` = number(3), `isInvalidPrev` = false → пропускается. Ожидается ли ошибка? Да, `5+3)` — невалидно. Но текущий код тоже пропускает эту проверку (после number `)` разрешён). Парсер выбросит `extraClosingParenthesis` при построении RPN (Parser.swift:37-39). ✓
- `5(-3)` → tokens: [5, (, unaryMinus, 3, )] → при `)` `prevToken` = number(3), `isInvalidPrev` = false → пропускается. Парсер вычислит `5 * (-3) = -15`. ✓
- `5+(-3)*2` → tokens: [5, +, (, unaryMinus, 3, ), *, 2] → при `)` `prevToken` = number(3), `isInvalidPrev` = false → пропускается. ✓
- `5++3` → tokens: [5, +, +, 3] → проверяется в case `.binaryOperator` (строка 329-335), не затронута. ✓
- `5(-3)` → tokens: [5, (, unaryMinus, 3, )] → `prevToken` при `)` = number(3) → `isInvalidPrev` = false → пропускается. Парсер: `5 * (-3)`. ✓

### Исправление 2: Подавление ошибок в `tryAutoEvaluate` (Дефект B)

**Файл:** `Sources/ViewModels/CalculatorViewModel.swift`  
**Метод:** `tryAutoEvaluate()` (строка 244)

**Текущий код:**
```swift
private func tryAutoEvaluate() {
    let trimmed = expression.trimmingCharacters(in: .whitespaces)
    guard !trimmed.isEmpty, !isTrailingOperator(expression), !hasUnclosedParentheses(trimmed) else { return }

    do {
        let value = try engine.evaluate(expression)
        result = formatter.format(value)
        resultDecimal = value
    } catch {
        errorMessage = error.localizedDescription
    }
}
```

**Новый код:**
```swift
private func tryAutoEvaluate() {
    let trimmed = expression.trimmingCharacters(in: .whitespaces)
    guard !trimmed.isEmpty, !isTrailingOperator(expression), !hasUnclosedParentheses(trimmed) else { return }

    do {
        let value = try engine.evaluate(expression)
        result = formatter.format(value)
        resultDecimal = value
    } catch {
        // Ошибки автовычисления не показываются пользователю —
        // они мелькают при наборе неполных выражений.
        // Ошибки отображаются только при явном нажатии "=" (метод evaluate()).
    }
}
```

**Обоснование:** Метод `tryAutoEvaluate()` — это подсказка, показывающая предварительный результат при вводе. Он не должен отображать ошибки, так как выражение в процессе набора может быть неполным. Единственное место, где ошибки должны отображаться — метод `evaluate()` (строка 97-116), вызываемый при нажатии `=`/Enter.

**Потребители `tryAutoEvaluate()` (верифицировано через grep):**
1. `appendCharacter()` (строка 76-78) — после каждого нечислового символа
2. `backspace()` (строка 135) — после удаления символа
3. `useHistoryEntry()` (строка 234) — при загрузке записи из истории

Во всех трёх случаях подавление ошибок корректно: `appendCharacter` и `backspace` — набор выражения, `useHistoryEntry` — загрузка (ошибки не нужны, так как выражение из истории должно быть валидным).
