### Шаг 1. Верификация проблемы (подтверждение диагноза)

**Цель:** Подтвердить, что корень проблемы — метод `memoryRecall()` в `CalculatorViewModel.swift`.

**Верифицированные факты:**

- **Файл:** `Sources/ViewModels/CalculatorViewModel.swift`
- **Класс:** `CalculatorViewModel` — `final class`, `@MainActor`, `@Observable` (строки 6–8)
- **Метод:** `memoryRecall()` — строки 176–181, видимость `public` (без модификатора = internal в Swift, но вызывается из UI через @Bindable)

**Текущая реализация `memoryRecall()`:**
```swift
func memoryRecall() {
    expression = memoryValue.description   // строка 177 — безусловная замена
    result = nil                           // строка 178
    resultDecimal = nil                    // строка 179
    errorMessage = nil                     // строка 180
}
```

**Проблема:** Строка 177 содержит `expression = memoryValue.description` — это **безусловная замена**. Любое содержимое `expression` теряется.

**Сценарий бага (пошагово):**

| Шаг | Действие пользователя | Вызываемый метод | Состояние expression до метода | Состояние expression после метода |
|-----|----------------------|------------------|-------------------------------|----------------------------------|
| 1 | Ввод "10" | `appendCharacter("1")`, затем `appendCharacter("0")` | (пусто) → "1" → "10" | "10" |
| 2 | Нажатие M+ | `memoryAdd()` | "10" | "10" (memoryAdd не меняет expression) |
| 3 | Нажатие "+" | `appendCharacter("+")` | "10" | "10+" (hasResult=false, оператор добавляется к выражению) |
| 4 | Нажатие MR | `memoryRecall()` | **"10+"** ← **вот здесь теряется!** | **"10"** ← memoryValue.description = "10", expression перезаписана |
| 5 | Нажатие "=" | `evaluate()` | "10" | результат = 10 (вычисляется только "10") |

**Ожидаемое поведение на шаге 4:** expression должно стать `"10+10"`, чтобы на шаге 5 вычислилось `10 + 10 = 20`.

### Шаг 4. Анализ взаимодействия с `tryAutoEvaluate()`

**Цель:** Убедиться, что изменение логики `memoryRecall()` не вызывает неожиданных побочных эффектов через `tryAutoEvaluate()`.

**Верификация цепочки вызовов:**

1. `memoryRecall()` (строка 176) — **не вызывает** `tryAutoEvaluate()` напрямую.
2. После `memoryRecall()` пользователь обычно нажимает оператор или цифру:
   - Если MR → "+" → `appendCharacter("+")` вызовет `tryAutoEvaluate()` (строка 77). Но выражение будет `"10+"`, а `isTrailingOperator("10+")` вернёт `true` (строка 252), поэтому `tryAutoEvaluate()` **ничего не вычислит** (guard на строке 239). ✅
   - Если MR → цифру → `appendCharacter("5")` вызовет `tryAutoEvaluate()`, но `isDigitOrDecimal("5")` вернёт `true` (строка 76), поэтому `tryAutoEvaluate()` **не будет вызван**. ✅

**Вывод:** Взаимодействие с `tryAutoEvaluate()` не создаёт побочных эффектов.

### Шаг 5. Анализ взаимодействия с `appendCharacter()` при hasResult=true

**Цель:** Убедиться, что изменение логики корректно работает в контексте метода `appendCharacter()`.

**Текущий код `appendCharacter()` (строки 60–79):**
```swift
func appendCharacter(_ char: String) {
    clearError()

    if hasResult && !isOperator(char) {
        expression = ""
        result = nil
        resultDecimal = nil
    } else if hasResult && isOperator(char) {
        if let dec = resultDecimal {
            expression = dec.description   // строка 69 — результат становится началом выражения
        }
        result = nil
        resultDecimal = nil
    }

    expression += char                   // строка 75 — добавление символа
    if !isDigitOrDecimal(char) {
        tryAutoEvaluate()                // строки 76–78
    }
}
```

**Сценарий из bug-репорта:** "10" → M+ → "+" → MR → "="

После шага "+" (вызов `appendCharacter("+")`):
- `hasResult = false` (после ввода "10" результат не вычислялся, resultDecimal = nil)
- Первый guard (`if hasResult && !isOperator(char)`) — **false**, пропускается.
- Второй guard (`else if hasResult && isOperator(char)`) — **false**, пропускается.
- `expression += "+"` → expression = "10+" ✅

После MR (вызов `memoryRecall()`):
- Текущий код: `expression = memoryValue.description` → expression = "10" ❌
- Исправленный код: `expression += memoryValue.description` → expression = "10+10" ✅

**Вывод:** Исправление корректно встраивается в существующий поток данных.
